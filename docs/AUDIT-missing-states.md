# 审计：「缺失状态 / 不可达展示」类缺陷（2026-09-18）

> **精简介**：本节起为 2026-10-04 的整篇重写（原文 449 行）；历史版本见
> `git show <hash>:docs/AUDIT-missing-states.md`：重写前最近一版 `9e29cd0`。
>
> **重写的取舍**：原文是"审计报告（§1–§5）+ 实施记录（§10）"——而 **§10 里每一条都已修**，
> 于是正文的"用户看到 XX"与文末的"已修"重复了一整轮。本版把它合成**一张闭环台账**：
> 每条只留 **形状（根因）/ 现在在哪修好了**。分类口径（A–E）与那条**最重要的方法论**保留在 §1。
>
> **与 [`AUDIT-redundancies.md`](AUDIT-redundancies.md) 的分工**：那份找「**多余**」（死代码、重复实现）；
> 这份找「**缺失**」—— 缺一档状态、缺一个生产者、声明了却画不出来。**方向相反，缺一不可** ——
> 而那正是首屏那个缺陷能活过好几轮审计的结构性原因（见 §1）。

## 0. 分类口径（A–E，五类其实是同一个根因的五个面）

| 类 | 判据 |
|---|---|
| **A 缺失状态 / 哨兵值复用** | 某个条件、字段或初值同时承担两个含义（「未知 / 还没到」与「确实是空 / 否 / 0」）。典型形状：`x.length === 0`、`x === null`、`x \|\| 默认值`、布尔初值。**判据**：对每个由状态驱动的渲染函数，**枚举它在运行时可能处于的状态**，逐个检查是否有互不相同、且各自真实的表现 |
| **B 不可达 / 从未被绘制的 UI** | 标记或样式存在，但在任何可达路径上都画不出来。典型形状：节点在首次绘制前被替换 / 清空、类名或 `data-*` 值**没有生产者**、可见性由永不成立的条件控制、初始状态属性无人清掉。**判据**：对每个元素问"谁把它变可见？那条路径走得到吗？"；对每条 CSS 规则问"这个键有生产者吗？" |
| **C 注释与实现相反** | 注释声称的行为代码没做；或注释说"某处有守卫 / 兜底"，而那条守卫在别的分支、或根本不存在 |
| **D 占位值与真实值不可区分** | 加载中用 `0`、`—`、空串、默认文案渲染，读起来与真实数据一样 |
| **E 现状文档的声明与实现不符** | 让这类缺陷长期不被发现的那一层（见下） |

### 0.1 为什么必须有 E 类：**文档担保是上一轮的"消音器"**

首屏那个缺陷逃过好几轮通读，主要不是因为难读，而是因为**三条文档互相印证"它已经有了"**：
一份现状文档写着 loading = 骨架屏、一份清单写着"状态矩阵完整"，而 HTML 里确实躺着一段 `.skeleton`。
于是任何"读文档下结论"的人**都会跳过它**。

> **结论（本文件最值得复用的方法论）**：
> **凡是文档声明"某状态已实现 / 某处已修 / 某令牌在用"的，都必须去代码里找一个生产者。**

### 0.2 范围与方法

- 范围：两版前端的全部 JS / CSS / HTML，约 **18 000 行** + 6 份前端相关文档。
- 方法：四路并行通读（V1 JS / V2 JS / 两版 CSS+HTML / 文档一致性），产出 25 条候选；
  **每条都由主代理人独立逐行复核**（读原文、算特异性、反向核对生产者），复核中剔除 1 条、降级若干条。
- **本轮没有起 dev server、没有跑套件、没有做浏览器实测**（用户明确"不要跑门禁"）⇒
  所有结论都是**静态核对**；凡需真实渲染才能定案的都进了"拿不准"，不写进确认项。

### 1.1–2.3 A 类：哨兵值复用

| 条目 | 形状（「未知」被渲染成了「已知」） | 现在 |
|---|---|---|
| **V1 分页写「没有可显示的记录」** | `total === 0` 同时表示"还没到"与"真的一条都没有"，而 `render()` 首帧就跑 | `update()` 增加 `loading` 入参；`pending = loading && total === 0` 时给「正在加载…」、页码标签留空 |
| **V1 头栏「正在加载…」与正文「加载失败」并存** | `showError()` 只换正文、不改头栏，而最后一次 `renderHead()` 是加载档写的；失败路径又不调 `render()` | `showError()` 里把头栏条数清空（失败时条数是**未知**的 ⇒ 既不给数字也不给替代文案） |
| **V2 `.overview__ghost` 从未被绘制** | `setValue()` 的"没变化就不动 DOM"判据用 `dataset.value`，而 `text` 从不写 `dataset` ⇒ 首次调用时 `undefined` 与首次传入的 `null` 被当成"相等"，在 `append(placeholder())` 之前就 return | `placeholder()` 接进首绘 |
| **V2 分页写「共 0 条」** | 与 V1 同形（`update()` 无加载档，`store.total` 初值 0） | 补 `pending` 档；**可对照**：筛选条对同一个"未知的 total"是**留空**的 —— 分页条是漏掉的那处 |
| **V2 错误态的列表头写「0 条记录」** | 计数档只有 `loading ? '…' : String(total ?? 0)`，`error` 落进"否则" | `error` 单列一档（`empty` 写"0 条记录"是**对的**，错的是 `error` 跟着走） |
| **两版分页的「失败档」** | 失败既不是"加载"也不是"空"：V1 的失败路径不调 `render()` ⇒ 分页停在「正在加载…」；用户点任一筛选 chip 又会把错误态换成"还没有任何记录"（**条数未知却给出确定结论，还抹掉唯一的重试入口**） | `store` 增 `error` 位；抽出 `renderPagination()` 作为分页那一格的**唯一**绘制点；两版分页各补 `unknown` 档（`error && total === 0` ⇒ **什么都不说**），**与列表共用同一条判据** |
| **V1 统计条首屏失败后永久空白** | `stats === null` 同时表示"首屏还没到"与"取数失败"；而注释承诺的"下一次轮询会补齐"**不会发生**（轮询从不重取统计） | 轮询里补 `refreshOverview()` |
| **V2 抽屉把"没取到"当成"从来没有过"** | `Array.isArray(activity) ? activity : []` 把"还没取到 / 取失败"与"确实没有活动"压成同一个 `[]`；清理状态那处把 `info === null` 渲染成**断言式**文案「清理任务还没有运行过」 | 加 `loaded` 标记 + `info` 空判 |
| **V2 顶栏把「未连接」折成「定时检查中」** | `pushState === 'live' ? … : pushState === 'connecting' ? … : 'poll'` ⇒ `'offline'` 落进 `'poll'`，那一档 UI **永远画不出来**（连 CSS 都只有两档） | 删掉无生产者的 `offline`，另补 `connecting` 的 CSS 档 |

> **这一族的结构性教训**：**同一个哨兵值会在多个组件里各写一遍**（分页、统计条、抽屉、顶栏各有一份自己的
> `total === 0` / `x === null` 判据）。补档时要过一遍**该组件的每一处出口** —— 当时只给 `update()`
> 加了骨架档，`showError()` 那条出口就把「正在加载…」与「加载失败」同时留在了屏幕上。

### 5.1–5.5 E 类：文档的声明与实现不符

这节最要紧 —— **审计报告、设计文档、README 都是别人（和代理）下结论时的前提**。
五条**全部已订正**，且订正落在**当时的现状文档**上（`README.md` / `docs/ui.md` / `docs/ui-v2-design.md`）：

| # | 文档声称 | 实际 |
|---|---|---|
| 1 | **js/css 的缓存是"短 TTL + `stale-while-revalidate`"**（⇒ 部署后有 ≤5 分钟的新旧混用窗口）—— 写在**安全基线**表里 | 实际是 `no-cache, must-revalidate`（**没有** TTL、**没有** SWR）⇒ 「≤5 分钟混用窗口」这件事**已经不存在**。这条最危险：读者会照它去"修"缓存 |
| 2 | 同一份文档内部**自相矛盾**两处：操作列宽写「4×44 + 3×**4** 间距 = **212px**」（同一文档另一处写的是 230px）；字号阶梯写「12/13/14/18/30px」（另一处写 13/14/16/18） | 实际 `--col-actions-coarse: 230px`（间距已由 4 提到 10）；`tokens.css` 只有 **4 档** `--fs-h1/h2/body/sm`。⇒ **两个口径都不对** |
| 3 | `--fs-display` 是用来画概览带主数字的令牌；另一份审计说"未使用令牌已清零" | `var(--fs-display)` 在 `public/**` **0 命中**。**顺带发现一个守卫缺口**：「令牌不空转」断言当时只扫 V1 ⇒ 这条漂移不会有任何东西报警 |
| 4 | 组件词汇表（自述"测试按此校验"）里的类名 / 属性**不存在**：`.spark`、`.preview-cell`、`.menu` 的 `data-open`、`.batchbar` 的 `data-count`、抽屉的 `data-open` | 实际分别是 `.overview__spark`、`.entry`、原生 `hidden`、`.batchbar__count`、原生 `[open]` |
| 5 | 数字 / 路径过时：V1 文件计数「6 张样式表 + 23 个 JS」；V2 控件「保留 **30px** 视觉尺寸」；主题脚本写成 `/ui/js/theme-init.js` | 实际 **7** 张 CSS / **24** 个 JS；V2 的 `--control-h: 34px`；V1 的是 `/ui_v1/js/…` |

> **复核中剔除的结论**（审计员的话本身也是需要被验证的断言）：
> 一条把文件 / 行号**张冠李戴**（声称某审计文件记着 `overview__ghost` 已修，而那个文件只有 239 行、
> 全文不含该串；那条声明的真实位置在**设计文档**里）；一条**引文不实**（声称某处写 V1 是"冻结存档、加弃用横幅"，
