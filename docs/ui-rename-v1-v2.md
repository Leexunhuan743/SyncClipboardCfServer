## 1. 为什么这不是一次 sed

**前车之鉴**：2026-09-15 把 V1 搬进 `public/ui_old/` 时，一次 `/ui/` → `/ui_old/` 的批量改写
**把 17 处接口前缀一起改了** ⇒ 界面从此去打 `/ui_old/api/*`（服务端没有这个命名空间）。
症状很隐蔽：**HTML/CSS/JS 全部 200，页面停在骨架屏**，线上存活了两天。

**这次的第一件事是测绘**（`grep` 全库）：`ui_old` 出现在 **33 个文件**；而 `/ui/` 这个前缀在 V2 里
同时扮演**两个角色**，必须分开处理：

| 角色 | 例子 | 处置 |
|---|---|---|
| 页面 / 静态资源 | `/ui/js/boot.js`、`/ui/css/*`、`/ui/app/` | → `/ui_v2/...` |
| **服务端接口命名空间** | `/ui/api/*`（两版共用的路由） | **保持 `/ui/api` 不动** |

**为什么保留 `/ui/` 而不是让它消失**（两条硬理由，都不是审美）：

1. **接口前缀压着它**：`/ui/api/*` 是两版**共用**的服务端接口，它在入口处靠
   `pathname.startsWith('/ui/')` 一类判据与"界面资源"区分 ⇒ 把 V2 的资源挪走之后，
   `/ui/` 这个前缀仍必须存在，它承载接口。
2. **老书签**：`/ui/` 是真实存在过的用户可见地址，留一层壳比 404 好。

**顺带收敛**：入口原来的判定是三岔（`isUiPath` / `isUiApi` / `isArchivePath`），其中两个界面面的
处理形状相同 ⇒ 合并成一条 `isUiAsset` 链（三个前缀共用），少一份会漂移的重复。

### 2.1 替换的实际做法

三类字面量**误伤面完全不同**，因此分三轮、各自带保护：

| 轮次 | 模式 | 保护措施 |
|---|---|---|
| ① V2 的 URL | `(["'\`(])\/ui\/(?!api)` | 要求前面是引号 / 反引号 / 括号 ⇒ 避开相对导入 `./ui/`、`../ui/` 与仓库路径 `src/ui/`；`(?!api)` 保住接口前缀 |
| ② V1 的整词 | `ui_old` | 无需保护：目录名与 URL 前缀**同时**变了，整词替换语义恒等 |
| ③ 仓库路径 | `public\/ui\/` | 尾部带 `/` ⇒ 不会误伤 `public/ui_v1/` |

**刻意不做批量替换的地方**：`src/**`（里面有 `app.all('/ui/*', …)` 这种**代码**）、
`docs/progress.md` 与 `docs/AUDIT-*.md`（历史记录，改了就是篡改历史）、本文件（叙述改名本身）。
这些全部手工逐条改。

## 3. 改名 / 搬目录的**四类残留**（本文件最值得复用的部分）

一次"改目录名 + 改 URL 前缀"会留下**四类**残留，**每一类的排查手段都不同** ——
只做前两类是常态，那正是这次连续补了三轮的原因：

| # | 类别 | 怎么找 | 是否会被门禁抓到 |
|---|---|---|---|
| ① | **被引用的文件路径** | 全库 `grep` 旧名 | 看有没有守卫读它（当时 `_headers` **没有任何守卫** ⇒ 漏了两天） |
| ② | **配置与测试里的路径字面量** | `_headers` / `robots.txt` / `wrangler.toml` / `deploy.yml` **逐个过** —— 按目录替换会整份漏掉它们 | 只有当守卫**动态发现**挂载点时才抓得到（写死清单的守卫只防改名、不防新增） |
| ③ | **运行时导航 URL** | `Page.navigate` / `goto` 的**模板字符串** —— `${BASE}/ui/app/` 这种形态**不在** `(["'\`(]` 字符类里 | **不会**：`test/manual/*.mjs` 不匹配 `*.test.*`，CI 不会红 |
| ④ | **散文里的"地名"** | `grep -n '/ui_v2/'` 之后**逐行问"它到底指哪一面"** | **不会**：它不是路径引用，任何正则都扫不到 |

**判据（第 ④ 类最容易做错）**：**叙述历史事件的句子，必须用事件发生当时的名字**。
用改名后才存在的名字去叙述一件按那个名字从未发生过的事 = 缺陷。
本仓库真实踩过两次：把「`public/ui_old/` 时 `/ui/` → `/ui_old/` 的批量改写」整词替换成
「`ui_v1` 时 `/ui_v2/` → `/ui_v1/`」—— 一件 2026-09-15 **从未发生过**的事。
自查办法：`AGENTS.md` §1 那条「改文档里写死的数字 / 文件名」的全文搜。

**第 ② 类的两个具体教训**：

- **`public/_headers` 整份漏改**（唯一影响运行的一处）：规则全留在已不存在的 `/ui_old/*` ⇒
  两版前端**同时**退回平台默认 `max-age=0`（丢掉"每次回源验证"的纪律与图标长缓存），
  而 `docs/frontend-checklist.md` 还把这件事记成"✅ 已完成"。**防复发**：`ui-guard` 后来加了两条
  结构判据 —— 规则路径必须在 `public/` 下真实存在、有 js/css 目录的挂载点都必须有 no-cache 规则，
  且挂载点集合**从 `public/` 动态发现**。
- **守卫写死清单只防改名、不防新增**：当时的判据把三前缀硬编码成 `['/ui', '/ui_v1', '/ui_v2']` ⇒
  将来加 `/ui_v3` 忘了配 `_headers` 时两条判据都不会红。已全部改为**从文件系统动态发现**。

## 4. 用户原话③的读法与处置

原话是「删掉『默认界面（V1）。开发测试版在 /ui/app/。』这一行」。那一行是 V1 顶部**提示条**的
**唯一内容** —— 只删文字会留下一条只有图标 + 关闭按钮的空条，显然不是想要的。

`initNoticeBar()`、**整份 `archive.css`**（它自述只为这条提示存在）、`ui-guard` 的对应条目与用例、
`docs/ui.md` 的资源数（89 → 88）与 V1 分表（38 → 37）。

## 6. 过程中踩到的坑（工具层，与改名无关但会再遇到）

- **`wrangler.toml` 不能写 `//` 注释**：那是**非法 TOML**，整份配置解析失败（部署直接挂）。用 `#`。
- **大段中文 `old_text` 匹配易错**：替换文本里含 `⚠️`（U+26A0 + U+FE0F），手写时漏掉变体选择符
  ⇒ 匹配失败。改为「写临时文件 + 按行号拼接」。
- **行尾**：仓库 `core.autocrlf=true`（索引 LF、工作区 CRLF）。脚本拼接引入的 LF 会让工作区出现
  混合行尾 —— **判据是 `git diff --numstat`**：某文件显示"整文件重写"就是行尾被改了。
- **`package.json` 的 `"type": "module"`**：临时辅助脚本会被当 ESM 解析，`require` 直接报错 ⇒ 用 `.cjs`。
- **只替换"一半"比不替换更危险**：出现在 URL 字符串里但**前面不是引号**的写法
  （`https://host/ui/__missing__）不会被引号锚定的规则命中，而同一行的**期望值**
  （`['/ui/__missing__']`）会被命中 ⇒ 请求与期望值不一致。**替换后必须逐个文件复核**，
  不能只看"总命中数下降"。
- **删一个 UI 元素要连带清三处**：删掉提示条后，HTML、两处 JS 接线、整份 CSS、守卫条目全部
  失去目标 —— 少清任何一处都会留下死代码或让守卫红。
