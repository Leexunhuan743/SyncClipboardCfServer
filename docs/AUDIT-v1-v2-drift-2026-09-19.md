## 1. 四条已修条目的机理（保留作判据）

- **F1 的机理**：浏览器对隐藏标签的定时器节流会让"不可见时的整页刷新"白跑；更关键的是 **marker 已被照常推进**，
  回前台那一刻 `unchanged` 为真 ⇒ 不补刷。⚠️ **措辞边界（复核时放宽）**："永久丢数据"**略严** ——
  可见态下的轮询仍在跑，列表最迟在**下一个可见轮询周期**被拉齐；**真正不可恢复的是及时性与闪帧**，不是数据本身。
- **F2 的机理**：`disabled` **挡不住 Esc 的 `cancel` 事件** —— 它照样结算成 `false`，而调用方的
  `if (!ok) return` 会把收行 / 刷新 / 提示整段跳过。
- **F3 的机理与那条自查补正**（**本节即 `progress.md` §91 引用的 §6**）：初版清单把 `search` 归为"不改变成员资格"，**那是错的** ——
  服务端为它生成 `Text LIKE ?`，**被它滤掉的行看不见、却仍留在选择集里**，与 F3 完全同型。
  `search` 已补入两版的 `MEMBERSHIP_KEYS`，两版注释与本节同一次改掉。
  集齐的判据是：**会改变结果集成员资格的字段 = `types / starred / deleted / range / after / before / search`**；
  排序 / 翻页 / 页大小**不在列**（它们不改变集合）。
- **F5 的机理**：选择条的方向文案读的是**选择集里那份对象**，而写操作只更新了 `items` 里那份。
