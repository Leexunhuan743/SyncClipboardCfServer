## 1. 来源与取舍（融合清单）

`clipserver` 是 FastAPI + WsgiDAV 的 Python 服务端：WebDAV 端点 + 钩住 `SyncClipboard.json` 写入落库
+ 一个 Web 历史界面。逐项对照后的处置：

| # | clipserver 的能力 | 本项目的处置 |
|---|---|---|
| 1 | WebDAV 服务端 | **已具备**（且更完整：PROPFIND 207、`DELETE /file/{name}`、无引号 multipart 兼容） |
| 2 | 剪贴板更新落库 | **已具备**（写在 `PUT /SyncClipboard.json` 与 `POST /api/history`，含版本 / 去重语义） |
| 3 | 类型识别 Text / Image / File / Group | **已具备**（`ProfileType` 枚举，含位掩码筛选） |
| 4 | 数据文件归档 | **已具备**（R2 `history/{Type}_{Hash}/{file}`） |
| 5 | **Web 历史界面** | **本项目新增**（下面的 5a–5k 是界面层独有的部分） |
| 5a | 列表分页、每页条数可选 | 新增：UI 支持 20/50/100/200/500，**官方 API 仍固定 50** |
| 5b | 类型筛选 / 搜索 / 收藏筛选 / 日期范围 | 复用官方查询语义（`Types` 位掩码、`SearchText`、`Starred`、`Before/After`）；日期范围支持预设 + 自定义，边界按**本地日界**计算 |
| 5c | 多列排序 | 新增：6 个排序字段 + 升降序；**官方 API 仍只有 createTime / lastAccessed** |
| 5d | 收藏切换 | 复用 `PATCH`（星标 / 置顶），与官方 PATCH 同一实现 |
| 5e | 删除 / 批量删除 | 单条复用 `PATCH isDelete`；批量是界面独有的选择集语义 |
| 5f | 文本预览、图片预览、文件下载 | 新增（数据经 `/ui/api/.../data`，同源 Cookie 鉴权） |
| 5g | 统计（总数 / 按类型 / 最近同步） | 复用 `statistics` 并补按类型分布 |
| 5h | 自动刷新新记录 | **改进**：由变更信号驱动（原实现是整页轮询），且只重拉当前页 |
| 5i | 登录 / 登出 / 会话 | 新增（签名 Cookie，见 §4） |
| 5j | **复制到剪贴板**（文本 / 图片） | 新增：文本走 `writeText`，图片走 `ClipboardItem`（非 PNG 先转码）。写入结果**可判别**（`unsupported` / `failed` + 底层原因），失败降级到预览 |
| 5k | **回收站**（查看已删除 / 恢复） | 新增：`deleted=true` 只看已删除行；软删**保留数据文件**（ADR D29），恢复把记录连同数据一起拿回来，见 §5 第 4 条 |
| 6 | `/api/info` 存储信息 | 新增为「部署信息」对话框，直接给出客户端该填的服务器地址 |
| 7 | Docker 部署 | **不适用**（本项目部署在 Workers） |
| 8 | Unix 风格 `/dav` 前缀 | **有意不实现**（ADR D15） |

**没有照搬的部分**：clipserver 的接口形状（`GET /api/history`、`/api/file/{id}`、`/api/stats`…）
与前端 JS 都没有移植 —— 那样会在同一个 Worker 上造出第二套语义。界面改用本项目已有的官方历史 API
作为数据面，只为自己需要的差异（可变页大小、多列排序、选择集、缩略图）新开 `/ui/api/*`。

## 2. 架构与边界

```
浏览器
  │  GET /                 → Worker：302 → `/ui_v1/`（默认界面；Accept: text/html 才跳）
  │  GET /ui/**            → 静态资源（`/ui/` = 跳转壳，送到 /ui_v1/）
  │  GET /ui_v1/**         → 静态资源（V1 = 默认界面）
  │  GET /ui_v2/**         → 静态资源（V2 = 开发测试版，本体在 /ui_v2/app/）
  │  GET /ui_shared/**     → 静态资源（两版唯一共享面）
  │      ↑ 四个面都先经过 Worker（见 §2.1），由它按界面开关决定"转回静态资源"还是 404
  │  GET/PATCH /ui/api/**  → Worker：src/ui/routes.ts（会话 Cookie 或 Basic 鉴权）
  │  GET /ui/api/**/data   → Worker → R2（图片预览 / 文件下载）
  ▼
Worker
  ├─ src/ui/*        UI 自己的面（本文件描述）
  ├─ src/routes/*    协议面（/api/history/*、/SyncClipboard.json、/file/*）—— 客户端依赖，**语义未动**
  └─ src/durable/*   SignalR 兼容 Hub（客户端连接用；界面通过 /ui/api/hub-ticket 换票据接入实时推送）
```

三条不变式：

1. **协议面无 UI 依赖**：`src/routes/*` 不 import `src/ui/*`；反向只允许 `src/ui/*` 复用
   `historyOps.ts` / `db.ts` / `storage.ts` / `serialization.ts`。
2. **写路径唯一**：界面上的收藏 / 置顶 / 删除都经 `historyOps.applyHistoryUpdate` ——
   与官方 `PATCH /api/history/{type}/{hash}` 是同一个实现（同一套版本判定、同一条广播、同一次 R2 清理）。
   于是"界面改了但客户端不知道"在结构上不可能发生。
3. **静态资源不占协议路径**：`public/` 下**不放** `index.html`；所有资源都在四个挂载点下，
   根路径留给 `PROPFIND`（客户端的探活与目录列举）。

### 2.1 界面开关（`UI_ENABLED`，默认开）

界面资源若由边缘直接托管，**"关掉界面"就无从实现**（边缘命中资源就直接返回，请求到不了 Worker）。
因此 `[assets]` 声明了 `binding = "ASSETS"` 与 `run_worker_first`：四个界面前缀的请求**先进 Worker**，
由它按 GitHub 仓库变量 `UI_ENABLED`（判定见 `src/uiEnabled.ts`）分流。

| | 界面开着（默认） | `UI_ENABLED=false` |
|---|---|---|
| 四个挂载点下的资源（含裸 `/ui` 的 `307 → /ui/`） | 转 `env.ASSETS.fetch()`，行为与"静态资源直接托管"**逐条一致** | **404**（纯文本 `Not Found`） |
| 挂载点下**不存在**的路径 | 资源 404 后**回落 Hono**，拿到 `notFoundPage`（四个前缀共用同一条链） | 404 纯文本（不产生界面痕迹） |
| `/ui/api/*`（含裸 `/ui/api`） | 照旧交给 Hono，守卫与业务不变。裸形态也归接口面 —— 它与 `/ui/api/` 是同一个命名空间的两种写法 | **404 JSON** `{"error":"not_found"}` |
| 根路径 `/`（`Accept: text/html`） | 302 → **`/ui_v1/`**（默认界面，少一跳） | **200 `Server is running.`**（不再把人引到不存在的界面） |
| 协议面 | 不受影响 | **不受影响** |

三条不变式由 `test/ui-guard.test.ts` 的「UI 部署开关」用例守着：关闭态**一次都不访问**静态资源且全 404；
开启态资源未命中必须回落出 404 页；**每个界面挂载点都在 `run_worker_first` 里**（挂载点集合从 `public/` **动态发现** ——
此前文档写着"删掉它会测试即红"，而实际上没有任何测试在读那份配置）。

线上每次部署后由 CI 冒烟按开关断言四个挂载点的页面与入口 JS
（`/ui/`、`/ui_v1/`、`/ui_v1/js/main.js`、`/ui_v2/app/`、`/ui_v2/js/boot.js`、`/ui_shared/brand/favicon.svg`）。

## 3. 模块划分

### 3.1 服务端（`src/ui/`，6 个模块，一个文件一个职责）

| 文件 | 职责 |
|---|---|
| `session.ts` | 无状态签名 Cookie：签发 / 校验 / 清除。纯密码学，不含路由与 HTTP 语义 |
| `guard.ts` | 鉴权：会话 Cookie 或 Basic；401 的响应形状与失败路径的请求体排空 |
| `query.ts` | 只读查询层：参数解析、白名单排序、LIKE 转义、分页、按类型计数、变更信号。拥有 `UiHistoryItem` / `UiListQuery` 等类型 |
| `routes.ts` | 路由装配：把 HTTP 映射到上面三者 + 复用协议层的 `HistoryDb` / `R2Storage` / `applyHistoryUpdate` |
| `maintenance.ts` | 维护面：数据完整性自检（R2 列举 × D1 期望目录差集）与保留策略在线读写（写 Meta 覆盖；**0 = 关闭该阶段**，留空 = 回落部署变量） |
| `notFound.ts` | 四个界面前缀未匹配路径共用的 404 页（只覆盖 UI 命名空间，不碰协议 404 语义） |

共享层的小幅开放：`db.ts` 导出 `rowToEntity` / `DbRow`（界面按自己的排序读同一张表 —— 另写一份映射，
两处对 NULL / 布尔列的解释迟早分叉）；`contentTypes.ts` 从 `routes/webdav.ts` 抽出
（`fileHeaders` 现在有两个真实调用方：WebDAV 附件与界面数据端点 —— 少一道 `nosniff` 就是一个存储型 XSS 面）；
`auth.ts` 抽出 `verifyCredentials`（Basic 头与登录表单共用）。

### 3.2 前端（`public/ui_v1/` = V1，真文件 + 原生 ES 模块，无构建步骤）

> **定位**：V1 是**产品界面 / 默认入口**；V2（`public/ui_v2/`，本体 `/ui_v2/app/`）是**开发测试版**
> （进去后顶栏版本号与登录页副标题都标着"开发测试版"），设计与实现见
> [`ui-v2-design.md`](ui-v2-design.md)。**本文件 §3.2 到 §11 描述的是 V1。**
> 保留 V2 的三个理由：① 零构建前端的**对照基线**；② 开发期的实验场；
> ③ 它与协议端点零关系，两版可以各自演进。
>
> **入口链必须一致**：站点根 `GET /` 的浏览器分支（`src/routes/webdav.ts`）与 `/ui/` 的跳转壳
> （`public/ui/index.html`）**都**指向 `/ui_v1/`，守卫见 `test/ui-guard.test.ts` 的「默认界面的入口链一致」。
>
> **挂载点分工**：页面与静态资源在 `/ui_v1/...`，服务端接口在 `/ui/api/...`（两版共用同一套，
> 前缀只写在 `public/ui_v1/js/api.js` 的 `API_BASE` 一处）。
>
> **V1 完全自包含**：不依赖 `public/ui_v2/` 的任何文件（守卫「V1 不依赖 V2」）；
> 唯一的例外是**共用层 `public/ui_shared/`**（品牌图标 + 无版本耦合的纯数据模块 `js/icons.js`）——
> **只允许逃到这一层**，逃进 `/ui_v2/` 一律红，且守卫要求 V1 确实有引用（防"共用层空转"）。
> 自包含的代价是"两份必然漂移"，因此 V1 自己的 `js/messages.js` 与 V2 的同名文件由一条**对等守卫**
> 钉住逐字一致（两份是**各自独立的副本**，不是共享模块；V2 真被删掉时连守卫一起删）。

`public/` 按职责分为五部分：V1、V2、`ui_shared` 共用层、`/ui/` 跳转壳，以及站点根的 `robots.txt` / `_headers`。
文件数量不再写进文档；新增或删除静态文件无需同步派生数字。

### 3.3 前端交互约定（改动这些地方前先读）

**下面的约定是功能正确性的一部分，不是风格偏好。** 每条后面的「判据」给出守卫位置。

1. **actions 返回结果，组件呈现结果。** `main.js` 的 action 返回 `true` 才算做成；行内按钮据此决定是否显示成功态。只看"请求发出去了"会把失败显示成成功。
2. **原地反馈优先于提示条。** 用户按的是哪个控件，结果（进行中 / 成功）就落在哪个控件上（`setPending` / `flashSuccess`）；提示条只承载需要解释或跨控件的反馈。
3. **同一视图内的刷新按行对账。** 用内容签名（`signature()`）比对，未变化的行**不重建** —— 重建整表会让每次轮询重载缩略图、打断动画、丢掉焦点。
4. **对话框的结算不依赖 `close` 事件。** 主路径（确认 / 取消）在**决定的当下**结算 Promise，`close` / `cancel` 只作旁路兜底（Esc、点背景）。依赖事件会让"事件不来即永不结算"，调用方 `await` 之后的收尾整段丢失 —— 实测 headless Chromium 上 `close` 事件就不来。
5. **删除成功后行就地收掉**，随后静默刷新补齐并对其余行对账；等下一次整页刷新才消失会读成"点了没反应"。收行时**必须把焦点交给邻居行的同一个按钮**（都没有时交给空状态主按钮），否则焦点落到 `<body>`，键盘用户得从页面开头重新 Tab。
6. **列表 / 统计 / 概览 / 活动趋势 / 变更信号 / 预览各有竞态守卫**：`begin()` 拿 ticket、`isCurrent()` 通过才允许落地，且 `catch` 里先看 `signal.aborted`（被取代不是失败）。少了这一步就是"陈旧响应覆盖新状态"—— 实测复现过：URL 与筛选控件说 Text、列表里是 46 行图片，且不会自愈。
7. **推送是轮询的加速器，不是替代品。** 可见时用 `/ui/api/hub-ticket` 换票据、建 WebSocket（`\x1e` 分帧、30 秒心跳 —— DO 静默 60 秒即断、退避重连），收到广播后去抖 300ms 再刷新列表 / 统计 / 趋势。批量写的广播已合并为每批一次（ADR D33）；去抖负责吸收连续批次与其它设备的通知。连接在线时轮询降为 **60 秒看门狗**；断线、拿不到票据（503）、环境不支持都自动回到 10 秒轮询，且**连续失败 5 次后进入 10 分钟冷却**（坏环境里每 ≤60 秒白试一次 ≈1.4k 请求/天），冷却结束或回前台时重试。**轮询代码不会被删**：看门狗存在的理由就是"广播没到"（DO 休眠、代理掐连接）。
8. **后台标签页主动断开推送。** 隐藏页的定时器被浏览器节流到 ≥1 分钟，30 秒心跳必然漏掉 60 秒静默窗口，那条路会退化成"断开→退避重连"的抖动（每次重连 = 一次票据 POST + 一次 WS + 一次 DO 唤醒），比它省下的轮询还贵，且连接不断时 DO 永不休眠（计费）。隐藏期间交给 30 秒轮询兜底。
9. **行内开关（收藏 / 置顶）就地更新、徽标同步。** 目标状态取**按下那一刻**的行数据（连点两次的第二次必须反向）；`patchItem` 采纳服务端回传的元数据（`version` / `lastModified` / `lastAccessed`），并就地替换徽标容器 —— `signature()` 必须包含**会变**的展示字段，否则轮询刷新后行不重建、时间停在首次渲染值（按"访问"排序时看起来像排序坏了）。
10. **深链接 `#Text-<hash>`**：`hash` 空闲（筛选状态在 query string），打开即预览那一条；写入片段前编码，读取时解码并拒绝路径分隔符；连续打开链接、改成无效片段与请求途中关框都以最新一次操作为准，迟到响应不能重新开框。关闭时清掉片段，避免刷新又弹出上一条。⚠️ 清 hash 依赖 `dialog` 的 `close` 事件：headless 的隐藏标签页里不派发 ⇒ 这条行为**只在真实浏览器可靠**。
11. **列表更新一帧落地，不做视图过渡、不播入场动画。** 视图过渡要对整个结果区做布局 / 样式快照（实测 6× 降速下一次"什么都没变"的切换多花 ~60ms，且随页大小上升），已移除。行入场错峰也**整条移除**（原形态：首屏前 12 行错峰淡入，尾巴 `(12 − 1) × 40ms = 440ms` —— 刷新后逐行冒出来读起来是"慢"，不是"来了"；它对的内容事件本来也只是首屏仪式）。CSS 的 `row-in` / `data-enter` / `--row-index` 与 `ENTER_STAGGER_LIMIT` 已一并清掉。判据：探针的 CLS 读数与首屏几何。
12. **筛选控件立刻画，列表等响应。** `store` 不触发绘制，而 `render()` 原先只在请求落地后跑 —— 从点击到响应这段时间里被点的那一段毫无变化（几百毫秒的"点下去没反应"，响应一到整块换掉，读起来就是卡顿）。现在 `applyFilters` 在发请求前先 `render()`：控件即时按下、结果区 `data-busy` 变淡，行仍是旧的，等响应回来再按行对账。
13. **切换类型不是「新视图」**：`全部 ↔ 文本` 在多数库里是同一批行，原先每次切换都整表重建 + 错峰入场 + 交叉淡入全是白做。现在只有**首屏（第一份非空结果）**走一次整表重建，之后一律按 key 对账、不播动画；`viewToken` 那套"视图标记"已删除（它当年只为入场动画服务）。
14. **类型计数在"迁就新视图"期间是隐藏，不是清空。** 切**范围**（回收站）会换掉整份计数，而 `countsForView` 的守卫要求"统计的归属视图与当前视图一致才允许显示"—— 中间的几百毫秒里 `byType` 是空的。此时**不写数字**、只给分段控件加 `data-stale`，由 CSS 把它藏起来：**占位不动**，因此 chip 宽度不变、搜索框不会被顶宽（清空会让五个 chip 各窄掉数字那一段，实测分段控件 −99px、搜索框被顶宽 50px 再弹回 = 用户报告的"点回收站之后搜索框闪一下"）。也**不要**改成"留住旧数字"：那会在屏上出现另一个视图的计数。判据：探针的 `TOOLBARSW`。
15. **批量动作后的焦点交接不许抢回用户已经放好的焦点。** `restoreFocus()` 有一圈 ~0.5s 的重试（等浏览器关闭模态后的补焦），判据是"只接手**无主**的焦点"：没有任何元素、或仍停在正在关闭的对话框里。焦点一旦落在别的可交互元素上（用户点了搜索框、点了下一行），立刻交还用户。判据：探针的 `FOCUSKEEP`。
16. **选择集里的那一份行对象必须与列表同步。** 复选框读的是行的**可变引用**（`rowRefs`），`toggleFlag` 成功后若该行在选择集里就换掉那一份并刷新选择条 —— 否则"这一行明明已经置顶、选择条还说置顶"会从批量按钮上冒出来。行的内容签名同时从 DOM 属性搬进模块内的 `WeakMap`（签名含最多 500 字符正文，50 行/页 = 每 10 秒一次无谓的属性写入）。
17. **行内操作那一栏（预览 / 复制 / 下载 / 删除）的五条硬约束**（2026-09-18）：
    ① **槽位固定**（活跃视图：预览=1、复制=2、下载=3、移动到回收站=4；回收站视图：恢复=1、预览=2、占位=3、彻底删除=4）—— 同一动作在同一列位，鼠标沿行间下移时按钮不跳；
    ② **触屏命中区不许挨着**：粗指针下按钮 44px、间距 10px（`--col-actions-coarse`），而"下载"的邻居就是"删除"（缝里点的后果不可接受）；
    ③ **禁用态必须还能被指针够到**：`[disabled]` 上不能写 `pointer-events: none` —— 那会把 `title`（"数据不可用，无法下载"）和 `cursor: not-allowed` 一起废掉；
    ④ **按 30px 按钮摊出来的列宽在触屏全都不成立**：按钮涨到 44px 后，「收藏 / 置顶」列与操作列都要跟着放宽 —— 少放宽的那一列会把按钮挤成两行，行高从 61px 顶到 105px（实测于 1024×768 触屏模拟）；
    ⑤ **文本行的下载按"服务端有没有这个文件"分两支**：带数据文件 → 取回**原字节 + 原名**（按钮叫「下载」）；内联文本 → 把正文包成 `text/plain` 存为 `Text-<hash 前 8 位>.txt`（按钮叫「下载文本」），长文本必须先取全文（列表里是 500 字符截断），否则会存下半个文件。文件名统一过 `safeFileName`（先 basename、洗掉文件系统不认的字符、去掉结尾的点 / 空白、限长 64 且**截断时保留扩展名**）。
    rest 态不透明度 0.7（SC 1.4.11 的 3:1），提亮判据是 `(max-width: 720px), (pointer: coarse)` —— 触屏没有 hover，**不能用宽度代替指针类型**。判据：探针的 `COARSE` 与 `DISABLED`。
18. **筛选生效时的出口按钮「清除筛选」**：最终形态 = **形状与批量按钮完全一致**（标准 `.btn`：36px、`--r-md` 圆角、字重 500、close 图标 + 文字），**只把颜色换成青色**（`--accent-soft` 底 + `--accent` 字 + 强调色描边）—— `.results__clear` 只覆盖三枚色令牌，形状全部来自 `.btn` 基类，两处形状必然一致。hover 规则必须与 `.btn:hover` 同块声明（基色会被 `.btn:hover` 按回去）。只在真的有筛选时出现，位置在结果区头栏「筛选中 · 共 N 条」右边。
19. **表单错误挂到字段上。** 两个表单（登录页、保留策略）在报错时给**出错的那个字段**置 `aria-invalid` 与 `aria-describedby`（分别指向 `#login-error` / `#retention-status`），并把焦点送过去；CSS 用 `.input[aria-invalid="true"]` 换描边色（**颜色只是加速识别，错误文案才是主通道**）。服务端的 500 / 429 不是"字段填错了"，只挂描述、**不标** `aria-invalid`（标了会撒谎）。判据：`ui-guard` 的状态矩阵断言。
20. **页脚的相关链接**：常驻入口是**项目名** `SyncClipboard CfServer`（本身就是链接，指向本项目仓库），带 `title`（仓库地址）：**可见文字是本产品的名字，`title` 才是"它会开到哪"**。悬停（细指针）或键盘聚焦（`:focus-within`）时在它**上方**拉出一张「致谢项目」卡片，列 README「致谢」里那六项及各自 URL（卡片标题与 `nav` 的 `aria-label` 逐字一致）。收起态是 `opacity: 0 + pointer-events: none`（**不是** `display: none`）—— 链接留在 Tab 顺序里；触屏没有 hover，那一档把卡片改成**常驻**。
21. **分页在窄屏的行结构**：「上一页 / 第 X / Y 页 / 下一页」必须**同一行且靠右** —— 靠 `.pagination__prev` 的 `margin-left: auto`（窄屏 spacer 被隐藏、这一组常常换行到第二行，只有 auto margin 两种情形都成立）。两条反面教训：范围文本与页码标签**不能共用** `pagination__range`（窄屏那条 `width: 100%` 会把页码也撑成整行，分页于是折成四行）；页脚那个浮层的包含块是**入口**而**不是** `.app-footer__inner`（锚整块时面板与入口之间会空出一条带子），但锚入口要同时满足：页脚 `align-items: flex-start` + 说明那格 `flex: 1 1 0; min-width: 0`（否则入口被挤到第二行）、面板宽度上限按**视口**算（按包含块算会把 55 字符的地址折成四行）。判据：探针的 `PAGER` 与 `FOOTER`。
22. **顶栏那枚「部署信息」胶囊的名字不许断行**：`.status__entry` 加 `white-space: nowrap`。中文没有词边界，没有这条时顶栏一挤就把那四个字压成「部署信 / 息」。代价是顶栏必须在**更窄**时也放得下，故跟着补两档让位：≤380px 只收间距（**一个控件都不隐藏**），≤280px 才让纯装饰的品牌图标走（顺序沿用 ≤560px 那条"要不要办事"的判据）。判据：探针的 `HEADER`。
23. **窄屏工具栏的三条**：
    · 「每页条数 + 刷新」是**一组**，整组 `margin-left: auto` 贴**行尾**（放得下与筛选并排，放不下整组落到下面一行、仍在右边）。「每页条数」**不再**在窄屏隐藏 —— 上一版把它让出去换了一整行，代价是窄屏**没有改页大小的地方**（只能手改 URL，那不是入口）。
    · 筛选 chip 的文案是 `收藏`，不是"仅收藏"（与 V2 对齐）。
    · **七枚 chip 的文字全都留着、图标与文字是叠加关系**（图标是扫读加速器）。展开收起两枚视图 chip 的文字会腾出 ~115px，而那 115px **全部**被 spacer 吸收 ⇒ 行中间出现一个大洞，比不折更糟；要折就得同时改那一行的对齐契约，而那件事本身没有收益。真正要修的是"被裁掉"：五枚带图标的 chip 合计约 470px > 窄屏可用宽度，而这一组是 `inline-flex` + 默认 `nowrap` ⇒ 溢出部分被 `html { overflow-x: clip }` **直接裁掉**。修法：窄屏允许 `flex-wrap: wrap`，内边距收窄让每行多塞一枚。**「全部」的图标不用 `list`**（与 `text` 在 14px 下几乎同形），也不用 `clipboard`（两版的品牌标记）⇒ 用 `inbox`（与 Gmail 的"收件箱 = 全部邮件"同一取向）。名字与数字一并写进 `aria-label`（计数未知时不写数字）。判据：探针的 `PAGERBAR`。
24. **筛选一变就清空选择集**：`setFilters` 对**会改变结果集成员资格**的字段统一清选择集（并刷新选择条），否则残留的旧快照会让"删除选中"落到当前筛选**看不见的行**上 —— 选 3 条文本 → 点「图片」→ 选择条仍说"已选 3 条" → 删除，被删的是列表里根本看不到的那 3 条文本。成员资格字段 = `types / starred / deleted / range / after / before / search`；排序 / 翻页 / 页大小**不在列**。⚠️ `search` 一度被漏掉，理由是"搜索只是高亮过滤"—— **与事实相反**：服务端为它生成 `Text LIKE ?`，被它滤掉的行看不见、却仍留在选择集里。判据：两版的 `MEMBERSHIP_KEYS`。
25. **选中态下点行体 = 切换选中，点空白 = 清空选区**：选区非空即"选中态" ——
    ① **行体点击**（非按钮 / 复选框 / 标签、未在划选文字）**切换该行选中**，**Shift+点击行体 = 范围选择**（锚点与复选框共用）；预览 / 下载等图标在按钮区里照常（行体点击用 `closest('button, input, a, label')` 排除）。
    ② **点空白清空选区**，空白 = **整页**（页面背景、表头底色、表格留白、卡片内边距、页脚），排除行体、`<dialog>` 内、控件与划选文字中的点击。
    ③ 选区变空即退出选中态，行体点击恢复「预览」。
    实现要点：**原生 Shift+点击会扩展文字选择**（mousedown 就开始，`click` 里 preventDefault 拦不住），故行体上挂 `mousedown`：选中态 + Shift + 非控件才 preventDefault；普通 mousedown **不拦**（用户要拖动划选文字）。清空选区一律走 `onClearSelection()`（**跨页全清**）—— 批量条「取消选择」与点空白共用；`onSelectAll(false)` 只清**当前页**，保留给表头全选框。
26. **悬停预览是渐进增强，信息绝不靠 hover 单独传达**（V1 唯一实现）：
    · 触发：`@media (hover: hover) and (pointer: fine)` 内悬停 **150ms** 出现；触屏**不挂监听**（走既有点击预览）。
    · **只在内容真正被裁掉时出现**：判据是 `scrollHeight > clientHeight` —— 正文是 `line-clamp:1` 的**纵向**裁切，而 `pre-wrap` 会让长文本换行铺满宽度 ⇒ `scrollWidth == clientWidth` 恒成立、横向判据**永远检测不到**（第一版就是这么漏的）。
    · **绝不接收指针事件**（`pointer-events: none`，本构件的**第一硬前提**）：浮层贴在行下方、必然压住后面几行，一旦它能命中，那几行的 hover 与点击就被吞掉 —— 实测鼠标顺着一列往下走"走不过去"，被压住的行连「收藏」都点不到。
    · **高度按行数封顶**（6 行），超出裁掉、**不给滚动条、也不给"还有更多"的说明行**：可滚动的前提是能移进去，与上一条直接冲突；而"这条被裁过"本来就有行内的 `长文本` 徽标与「预览」按钮在说。
    · **纯视觉，不承担无障碍职责**：完整文本本来就在 DOM 里（只是被 CSS 裁切），读屏不需要它 ⇒ 浮层 `aria-hidden="true"`、**不挂** `aria-describedby`（第一版写的 `role="tooltip"` + `aria-describedby` + focus/blur 监听是**死代码** —— 触发元素是个不可聚焦的 `div`）。取全文的**可访问**路径是行内的「预览」按钮。
    · 行被对账重建 / 移出文档之后由 `update()` 调 `prune()` 主动收起：指针**不动**时节点被 `remove()` 不会产生 `mouseleave`。
    · 短元数据（时间列相对→绝对、图标按钮动作名）继续用原生 `title`；**只有长内容**才用本构件。
    判据：`tooltip.js` + `list.js` 的 attach/prune + 探针的 `HOVER`。
27. **回收站的行内出口各占一个固定槽位，且都过确认框**：
    · 行内动作三个 —— **恢复固定槽 1**（本视图的主操作）、**预览固定槽 2**（紧挨「恢复」的右边，与槽 4 那个不可撤销的之间留一整格 —— 常用的无害动作不该贴着危险动作）、**彻底删除固定槽 4**（与活跃视图的"移动到回收站"同位），槽 3 是等宽占位。理由同活跃视图：动作按类型追加会让"哪个按钮在哪一列"逐行不同，而切换视图后误按的代价是"把记录恢复出去"或"把它永久删掉"。
    · 两处入口：行内「彻底删除」+ 选择条「彻底删除选中」（回收站视图专有）。**没有"彻底删除少量/中量"的入口时，用户只能整罐倒** —— 这正是它存在的理由。
    · **都过确认框**（不可撤销），文案住在 `messages.js` 的 `purgeConfirmSpec` / `batchPurgeConfirmSpec`，与 `deleteConfirmSpec` 的差别（软删 = 进回收站 vs 彻底删除 = 行也没了）**必须写在句子里**。
    · 服务端**只删 `IsDeleted != 0` 的行**（判据在 SQL 里）：活跃记录走不到这条路径 ——"绕过回收站直接真删"不是本界面的能力；删成功后**顺带清掉它的数据目录**（回收站里是真数据，这条出口的语义就是立刻连字节一起没）。
    · **「恢复」不按 `hasData` 禁用**：真回收站保留了数据文件，两类记录都能恢复。于是界面里**没有**"不可恢复"这个状态。
    判据：`list.js` 的 `buildActions` + 选择条 + `main.js` 的 purge 分支 + `ui.md` §5 的 `batch-purge` 行 + `protocol.md` §10 的两行偏离登记。
28. **长批量在途可中止，中止点是"批"的边界**：只有传入 `cancellable: true` 的分片批量在确认框**在途**时把「取消」变成「**中止**」；单条与清空不接中止信号，在途时禁用取消（✕ 与 Esc 同样挡住 —— 在途关框会让调用方把"已成功"读成"用户取消"）。点中止**不关框**：停掉后续批次，把「已生效 N 条」写在框里。
    · 粒度由服务端决定：**一次请求内部不会被打断**（那 100 条一定跑完）⇒ 中止点天然落在批与批之间，不会留下半条记录。
    · 中止**不是失败**：批量循环返回 `{…, aborted: true}` 而不是抛错（超时仍然抛，两者用 `error.name` 区分 —— 别合并成"都是异常"）。
    · 写批量只在选中数 **>100**、确实会发下一片时开放「中止」；批量复制是读请求，可连在途那一片一起取消。单条动作与清空是单次请求，发出后无法保证服务端停止，**因此不显示会误导用户的「中止」**。
    · **没有对话框的那几个，中止键在选择条上**：那枚按钮在途时变成「中止」—— 同一个键换一副面孔，与框里的「取消 → 中止」是同一条先例。带这个标记的是复制选中 / 收藏 / 置顶 / 恢复；对话框驱动的删除 / 彻底删除**不带**（它们的中止键在框里）。背景列表刷新时保留在途按钮并暂时禁用其它批量按钮；无对话框批量任务互斥。
    · **读与写的停法不同**：批量复制是**读** ⇒ 连在途请求一起掐断，且**全文没取齐就不动剪贴板**（中止的语义只有一句"什么都没写"）；写批量一律**按批停** —— 服务端可能已经应用了一部分，界面必须能如实报数。
    判据：`confirm.js` 的 busy 分支 + `api.js` 的 `isAbortError` / `aborted` + `messages.js` 的 `batchAbortedText`（两版逐字一致）。
29. **预览框里的「编辑」是两态机 预览 ⇄ 编辑，保存 = 新建一条记录**：
    · **只对 `Text` 开放**（其它类型没有"编辑正文"这回事）。
    · **保存的是新记录，不是改这一条**：文本记录的 `hash = SHA256(utf8(正文))`，正文一改 hash 必变 ⇒ 在协议模型里它就是**另一条记录**。服务端走 `addRecordDto`，**只广播 `RemoteHistoryChanged`、不碰当前剪贴板** ⇒ 其它设备只是多一条历史。「编辑」按钮的 `title` 就把这句写出来。
    · **保存后不关框**：正文换成刚保存的那段，另弹全局提示「已保存为新记录」（短文本附准确字符数）；列表在框**背后**静默刷新。提示条宿主会临时停靠进最上层对话框，确保模态打开时提示仍可见、可操作。复制 / 下载一律跟着**屏幕上这段**走（`currentText` 是唯一来源）。
    · **「没改字」判据必须先归一化行尾**：`<textarea>` 的 `value` 会把 CRLF 折成 LF，而记录里存的常常就是 CRLF ⇒ 直接比会得出"改过"，从而让**只点一下保存**凭空生成一条"只差行尾"的新记录（实测踩到）。
    · **Esc 在编辑态只退出编辑、不关对话框**：一段几千字的编辑不该被一个 Esc 丢掉。非编辑态的 Esc 行为不变。
    · **`> 1 MiB` 不给编辑**：按钮 `disabled` **且带 `title` 说明原因**（禁用不带原因等于把用户堵死在这里）。上限与服务端 `UI_TEXT_CREATE_MAX_BYTES` 同值（纵深防御）。
    · **保存失败留在编辑态**：原因**就地**渲染在 `<textarea>` 正下方（`role="alert"`），textarea **静态** `aria-describedby` 指向它（目标常驻、无错时 `hidden`），焦点送回正文里；用户改的内容一个字不动。只有**正文本身不合规**（服务端 400）才加 `aria-invalid` —— 网络 / 500 不是字段的问题（第 19 条同一条判据）。
    · **保存途中不许关框**：`saving` 期间 ✕、点背景、取消键与 Esc 都被挡；否则失败原因会与未保存的输入一起丢在屏幕外。
    · **保存成功后对话框改指向新记录**：预览框换掉 `currentItem` 并**重画头部**，深链接也换成新记录的 hash。不改的话屏幕上是"头部说旧记录的字符数、正文是新文本"，且刷新页面会弹回旧那一条。⚠️ 这条依赖 `api.createText` **过归一化**：服务端按上游惯例把 `type` 序列化成数字，不归一化时 `type` 是 `0`，于是「文本」那一支全判错（自审时实测踩到）。
    · **头部、复制提示与保存提示使用同一字符口径**：服务端 `size` 是 UTF-16 码元数，**不能标成用户看到的「字符」**。正文不超过 20,000 码元时用 `charCount()` 按字素簇计数；大文本在头部写「长文本」、提示条省略数字，避免为一句说明全量运行 `Intl.Segmenter`（1.1 MB 正文实测需 169ms）。深链接加载壳缺少 `size` 时头部暂不写数字；从列表打开被截断的长文本时，**不拿那 500 字冒充全文**，全文到达后才按真实正文显示。
    判据：`preview.js` 的 `enterEdit` / `exitEdit` / `renderView` / `renderHead` + `main.js` 的 `createTextRecord` + `api.js` 的 `createText` + `messages.js` 的三条文案（两版逐字一致）+ `ui.md` §5 的 `POST /ui/api/history` 行。
30. **行内徽标靠内容列的右缘站成一列；内容格过窄时徽标让出正文行**：
    · **紧贴正文是错的**：那样徽标落在"正文结束的地方"，同一屏里位置各不相同（1440 实测差 205px）⇒ 一屏之内位置各异的徽标**没法扫读**，而"哪几条是置顶的"正是徽标存在的意义。
    · 实现：徽标容器 `margin-left: auto` 贴内容格右缘；窄屏（≤860px）用 `@container` 把它换到正文下一行。
    · 判据：`row-content.js` 的 `buildFlags` + 探针的徽标几何。见 ADR D35。
31. **「删除」只指不可撤销的那一档；软删一律叫「移动到回收站」。** 界面里出现"删除"两个字的地方（按钮、确认框标题、批量动作）必须真的是不可撤销的那一个；有疑问的一律改成「移动到回收站」。判据：`messages.js` 的文案 + 两版的按钮文案。
32. **预览页脚的最左一格是"视图级销毁动作"，钉在左缘**：活跃记录「移动到回收站」/ 回收站记录「彻底删除」，与行内槽 4 同一个 action。它钉左缘（不与右侧的主操作混排）是为了让"危险动作"在每一条记录上都出现在同一个位置。
33. **回收站视图的「清空回收站」常驻在操作带里、「取消选择」的左侧**：没有选中时那条带子只装它。它**不需要**先选中才能用（"整罐倒"是最常见的诉求）。
34. **顶栏在向下滚时整条滑出，向上滚立刻回来**：折叠用位移而不是 `display: none`（避免布局跳动），且**必须有判别力**——触屏上快速回弹不应当成"向上滚"。
35. **对话框开着时的提示条：把宿主搬进最上层对话框，而不是在框里另造一条。** 两条提示条（框内、框外）会各自计时、各自离场，用户的观感是"提示闪了两下"。搬宿主 = 一条提示条，位置也对（在最上层）。
36. **快捷键：少而稳，每条都必须有可见的等价按钮。** 快捷键是**加速器**不是唯一入口 —— 任何一个只能靠键位到达的功能都是缺陷（可发现性 = 帮助浮层里列着，且工具栏有「?」入口）。帮助浮层的目录与派发器读**同一份表**，所以"帮助里写的"与"实际绑的"不会漂移。见 ADR D37。
37. **键盘可用性：快捷键只是一半，另一半是"只用键盘能不能把整页用完"。** 判据是**逐站走查**：从跳转链接开始，Tab 能不能到搜索、到列表、到行内每个动作、到分页、到对话框；方向键能不能在行间移动（到相邻行的**同一个控件**，不改 Tab 停靠点数）。
38. **只用键盘走一遍整页（真实按键的逐站记录）。** 这条不是新约定，而是第 37 条的**执行方式**：必须真的按键走一遍并记录每一站，不能用"代码里看起来可达"代替。已知的真实缺口记在 Git history。
39. **行内动作的载荷必须现读行的可变引用（`ref.item`），不能用构建期的快照。** 行被对账重建后，构建期快照仍是旧对象；用它发请求会把"上一次的状态"写回去（实测出现过"点下载却用到旧 hash"）。判据：`list.js` 的 action 载荷 + 两版同形实现。

### 3.4 共用层（`public/ui_shared/`）—— 两版唯一的共享面

规则：**只放不随某一版演进的东西**。

| 允许 | 例子 |
|---|---|
| 品牌资产 | `brand/favicon.svg` / `favicon-32.png` / `apple-touch-icon.png` |
| **无版本耦合的纯数据模块** | `js/icons.js`（常量路径表，不接受输入、不依赖任何一版的其它模块） |
| 将来的双语 / 翻译资源 | —— |

**不许放**：两版"实现有意不同"的模块（`format` / `dom` / `filters` / `api` / `messages` …）——
搬进去就把"改一版"变成"两版一起变"，那正是这条红线要防的。

判据由 `test/ui-guard.test.ts` 给出：**V1 的模块只允许逃到 `../ui_shared/`**，
逃进 `/ui_v2/` 一律红，**且必须确实有引用**（防"共用层空转" —— 一个没人 import 的共享模块只是死代码）。

## 4. 鉴权模型（ADR D13）

- **会话 Cookie**：`base64url(payload).base64url(HMAC-SHA256)`，payload 为 `{u, exp}`。
  密钥由 `PASSWORD` 经 HKDF-SHA256 派生（固定 salt / info），因此**改口令即让全部已签发会话失效**。
- **零存储**：不建服务端会话表（Workers 没有可依赖的进程内状态，D1 会话表会让每次页面请求多一次写库）。
- **登出只清本机 Cookie**，不吊销已签发的令牌 —— 兜底通道是改口令。要"登出所有设备"需要新的机制
  （方案与代价见 [Issue #3](https://github.com/Leexunhuan743/SyncClipboardCfServer/issues/3) §2.2）。
- **两条通道**：`/ui/api/*` 接受会话 Cookie **或** Basic；协议面只接受 Basic。
  守卫在受保护路由**之前**注册 —— 顺序写反会让端点照常工作但不再要求凭据，`ui-guard` 的遍历式断言会红。

## 5. API 契约（`/ui/api/*`）

这一层**不属于协议契约**（官方客户端不感知任何 `/ui/*` 路径），但与协议面**共用**同一张表、
同一套行映射与写路径。**完整端点清单以 `src/ui/routes.ts` 和 `test/ui-guard.test.ts` 的 `EXPECTED_API_ROUTES` 为准**；不再复制到第二份说明文档。

本文只登记**与界面设计强相关、或行为上有陷阱**的几条：

| 端点 | 要点 |
|---|---|
| `GET /history` | `pageSize` ≤ 500；6 个排序字段（表头给了 5 个可点列，`id` 没有可见列）；正文截断到 500 **码点**并带 `textTruncated` |
| `GET /history/:type/:hash/data` | 支持单区间 `Range`（206 / 416）—— **只给这个端点**，协议侧忽略 Range 是对齐上游的有意行为 |
| `POST /history` | 新建一条**文本**记录（预览框「编辑」保存用，正文 ≤ 1 MiB）；落库后回读该条 |
| `PATCH /history/:type/:hash` | 收藏 / 置顶 / 删除；也承接"触碰访问时间"（见第 7 条） |
| `POST /history/batch-update` | ≤ 100 条 / 次，有界并发 10，整批一次广播 |
| `POST /history/batch-meta` | ≤ 100 条，取**完整正文** |
| `POST /history/batch-purge` | 只删 `IsDeleted != 0` 的行并清其数据目录；不广播 |
| `PUT /settings` | 保留策略：数字 = 覆盖、`null` = 清除覆盖回落部署变量、缺省 = 不改动 |
| 缓存 | JSON 一律 `no-store`；**数据端点自带 `private, max-age=60`**（预览 / 缩略图复用） |

**界面直接依赖的四条行为**：

1. **`pageSize` 与 `sort` 是界面的差异诉求**（官方 API 固定 50 条、只有两个排序字段），
   其余筛选语义全部复用官方查询。
2. **`/history` 的 `pinnedFirst` 默认 true** —— 置顶记录恒排在最前（用户定的口径：
   **始终**优先，这个接口没有"默认排序"这一档）。
3. **写入的"触碰访问时间"**：界面在**复制 / 下载成功之后**发一条
   `{lastAccessed, lastModified, version}` 来推进该记录的访问时间 ——
   因为"使用一条记录"这件事在协议语义里由客户端负责，服务端只存回。
   载荷回显 `version`，使落库改动的只有访问时间：**版本不动则客户端随后的同步不判冲突**。
4. **回收站是可恢复形态**：软删只置 `IsDeleted=1` 且**数据文件保留**，
   恢复把记录连同数据一起拿回来；「彻底删除」与「清空回收站」是立刻释放 R2 空间的出口。
   "数据不可用"这一标注只在 **R2 对象确实缺失**时出现（`data_missing`），与是否已删无关。

## 6. 不做什么（以及为什么）

| 项 | 理由 |
|---|---|
| 多租户 / 多用户 | 上游就是单账号 + 硬编码 UserId；界面跟着这个边界 |
| 服务端会话表或内存会话 | 见 §4（零存储是刻意的） |
| 界面直连 SignalR **而不经票据签发** | 浏览器建 WS 时带不了请求头，票据就是那条通道 |
| Web 字体 | 自托管 + 国内网络：外部字体 CDN 大概率加载失败，会出现"先无字后有字"的闪烁（比系统栈更糟） |
| `/dav` 前缀别名 | ADR D15 |
| JSON-LD / `og:image` | 无现实实体 / 域名构建时未知 |
| 服务端缩略图 | Cloudflare Images 路线属独立立项，见 [Issue #3](https://github.com/Leexunhuan743/SyncClipboardCfServer/issues/3) §2.10 |

### 6.1 同一文档重复初始化（实测触发过）

应用若被以 `/ui_v2/app` 与 `/ui_v2/app/` 两个 URL 同时加载（V1 同理：`/ui_v1` 与 `/ui_v1/`），
模块图会出现两份，`boot()` 被第二次求值时挂载点已被上一次替换掉（`getElementById` 返回 null）
→ 半渲染 + 报错。已在装配入口用"已挂载即退出"的守卫挡住。

## 7. 安全

- **同源 XSS 面**：附件与 API 同源，浏览器会为同源请求自动带上已缓存的 Basic 凭据 ——
  一条注入的脚本就能读走全部历史。界面因此：
  · **不提供任何插入 HTML 的途径**（`dom.js` 只造节点、不设 `innerHTML`）；
  · 附件响应走**默认-deny 的内联白名单**：只有图片（除 svg）、`text/plain`、`text/csv`、
    `text/markdown`、`application/json`、`application/pdf` 允许内联，其余一律 `attachment`；
    HTML / XML 家族**按后缀判定**（含 `+xml`）另加 CSP 沙箱。判据从"枚举 4 项可渲染类型"改成
    后缀判定，理由是换 MIME 表时 `.xml` 会变成 `text/xml`，只换表就会让它"浏览器可渲染、却不加任何加固"。
- **`?next=` 只接受同源目标**：前缀比较不够（`https://evil`、`//evil`、`/\evil` 都要回落），
  独立成纯函数以便测试直接覆盖。
- **来源校验**：`/ui/api/*` 的状态变更方法校验 `Origin` 与 `Sec-Fetch-Site`，外源 403。
- **内容类型**：JSON 写端点只接受 `application/json`（跨站**表单**能直接发 POST 且不过 CORS 预检，
  而 JSON 必须由脚本构造 ⇒ 纵深防御）。
- **CSP** 由 `public/_headers` 声明：`default-src 'none'` + 逐项白名单（见 §3.2 的站点根行）。

## 8. 设计系统与动效

方言取 **product**（数据表 + 筛选 + 对话框）：圆角 8/10/6px、边框优先于阴影、句子式标签、表格用 `<table>`。
调色板是**暖中性底 + 单一强调色（深青）+ 星标琥珀** —— 两个色相加一套中性色；
**刻意避开紫→靛渐变**（生成式页面最可靠的识别特征）。

动效的准入规则只有一条：**每个动效都必须对应一个真实的内容事件，关掉它以后信息不丢**。
当前清单（`motion.css` 的表与本节一一对应，改一处就同步另一处）：
① 行高亮闪一次（别处改了这条记录）；② 行离场淡出（删除成功后就地收掉那一行 —— 只淡出不做位移，
表格行位移会让整列错位）；③ 成功对勾弹入（原地成功态）；④ 星标弹出；
⑤ 浮层进出；⑥ 跨文档视图过渡（登录页 → 列表页）。

**已移除的两条**（别再照旧稿加回来）：结果区整块交叉淡入（实测 ~60ms 成本且无信息）、
行入场错峰（用户要求：逐行冒出来读起来是"慢"）。

### 8.1 按下反馈（`:active`）

状态矩阵里的一格，不是内容事件。实现散在各组件表里，只有两条规矩：
可点控件有可视的按下反馈；`prefers-reduced-motion` 下它不是动画（是瞬时状态变化），故不受降级影响。

### 8.2 「到达并停住」：静止页面必须真的静止

V1 里**没有** rAF、没有插值循环、没有弹簧解算（唯一的时间循环是推送保活心跳）。
浮层是这一族的第一个消费者：按"出现即定住、不跟指针走"实现 —— 只有 CSS 定位 + 两个定时器，
没有滤波器。判据：探针读到静止态 `runningCount: 0`。

## 9. 生产打磨（逐条对照 production-polish 清单）

清单里的每一项都是「要么在、要么是缺陷」，故逐条给出结论：

### 9.1 头部与元信息

每个页面有唯一的 `<h1>` 与自洽的 `<title>`；`lang`、`viewport`、`color-scheme`、主题色齐备；
`favicon` 与 `apple-touch-icon` 指向共用层；`<meta name="robots">` 与站点根的 `robots.txt` 构成两道。

### 9.2 404 与爬虫

- **设计过的 404**：`src/ui/notFound.ts` 服务四个前缀下未匹配的路径
  （协议命名空间仍是 JSON / 文本 404，语义不动）。
- `robots.txt` 放**站点根**（爬虫只读根路径）—— `Disallow: /` 与页面里的 `noindex` 构成两道。

### 9.3 非快乐路径的状态

骨架屏、三种空状态（还没有记录 / 筛选中无结果 / 回收站为空）、首屏失败的**错误态 + 重试**、
失联横幅（`role="status"`，持续状态不用 toast）、`data-busy` 的整块降对比、登录页的错误位。
空状态还带"下一步动作"（清除筛选 / 如何配置客户端）。

> ⚠️ **"文档里写了"不等于"跑起来是这样"**：骨架这类状态必须真的打开页面看见它。
> 历史上骨架只存在于静态标记里、在数据到达前就被换掉，首屏真正的占位其实是空状态
> （库里有上千条时"还没有任何记录"那句话就是假的）。

### 9.4 深色模式

语义令牌同名不同值；`color-scheme` 按**生效主题**声明（不是跟随系统），否则浅色系统 + 应用内切深色时
会混进浅色原生控件。对比度逐色实测（类型徽标四色两套全部 ≥4.5:1）。

### 9.5 让页面「像成品」的小东西

不溢出（窄屏横向溢出为 0）、数字成列不跳（`tabular-nums`）、焦点可见、命中区 ≥44px、
长文本有裁断、图标按钮都有名字。反例也记着：那枚「部署信息」曾只有一枚无标签的 ⓘ ——
"第一次使用者找不到客户端该填哪个地址"，所以**可见文字留着**（见 §3.3 #22）。

### 9.6 机器可读的结构

地标齐全（`header` / `main` / `footer` / `nav`）、`<table>` 语义、`aria-sort` 只在排序真的生效时加。

### 9.7 分析与第三方

**零第三方**：没有分析脚本、没有外部字体、没有 CDN —— CSP 因此可以收到 `default-src 'none'`。

### 9.8 十项人工检查

逐项执行过（键盘走查、深色、窄屏、打印、离线、慢网、读屏语义、缩放 200%、强制减少动效、只读模式），
结论与遗留缺口在 Git history 对应小节。**未验证的项要明说**：本站没跑真实读屏，
全部无障碍结论由 DOM / ARIA 契约推断。

### 9.9 窄屏是一个具名的降级，不是副作用

每个断点都要能回答"牺牲了什么"（写在 CSS 文件末尾的注释里）。
**一条取舍被推翻时，要在新记录里写清"为什么当时那么换、为什么现在不换了"** ——
否则下一轮会把它当成 bug 改回去。
移动端必须实测的四个量：横向溢出、可点元素最小尺寸、首屏内容起点、软键盘弹出后输入框是否可见。

**三条纪律**（都是踩过坑才写下的）：

1. **"DOM 在" ≠ "看得见"**：几何 / 可见性类的判据必须读真实浏览器里的值，不能靠源码推断。

   否则 `findings=0` 与"所有判据都真跑过"是两件事。
3. **只 `console.log` 不算判据**：判据要进那个统一的 `findings` 数组并影响退出码。

## 11. 性能预算与探针（改动前端时按这一节量）

### 11.1 预算

| 项 | 门槛 |
|---|---|
| 首屏请求数 | overview + 列表并发（`activity` 不阻塞首屏） |
| 首屏 CLS | ≈ 0（骨架占位与真实同高；结果区预留最小高度） |
| 一页 500 行的正文载荷 | 服务端截断到 500 字符（一页 500 行 × 每条几十 KB 就是几十 MB 的 JSON） |
| 轮询成本 | 推送在线时 60 秒看门狗；离线 10 秒；隐藏页 30 秒 |
| 行 DOM 重建 | 仅签名变化时 |
| chrome 层写入 | 无变化不写 DOM（先比后写） |

### 11.2 探针步骤

起 dev server（**端口 8787**）→ 按 §10 的三个工具跑 → 确认**零 console 错误、零失败请求**、退出码 0。
至少覆盖**一档宽 + 一档窄**：窄屏是**另一套布局**（概览带折行、趋势图独占一行），
历史上一个只在窄屏出现的首屏 CLS 缺陷就是这样被找到的（宽屏读数 0.0026，窄屏 0.1217）。

### 11.3 已量出并据此定下的三条约定

① 结果区**不做**视图过渡（~60ms/次且随页大小上升）；② 首屏**不播**行入场动画；
③ 推送在线时轮询降为看门狗（一个开着的标签从 ≈8.6k 压到 ≈1.4k 请求/天）。

### 11.4 已知的固有成本（不打算优化）

`statistics.totalFileSizeMB` 每次全桶列举 R2（单用户规模 ≈ 数次调用）；
长轮询队列上限按连接计；Group 上传的峰值内存 = body + 2×解压。

### 11.5 测量窗口

探针读数受机器负载与 dev server 预热影响，故：**同一轮对比必须在同一次会话内测**，
且改动前后各重跑一遍；跨会话的读数只作趋势参考，不作判据。
