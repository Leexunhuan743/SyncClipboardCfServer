# Web 历史界面

> V1 `/ui_v1/` 是默认产品界面；V2 `/ui_v2/` 是开发测试版。本文是唯一 UI 权威文档：
> 只写当前边界、交互不变式、安全和验证方法。历史缺陷、迭代过程与视觉推演留在 Git 历史。

## 1. 架构边界

| 面 | 路径 | 说明 |
|---|---|---|
| 官方协议 | `/api/*`、`/SyncClipboard.json`、`/file/*`、`/SyncClipboardHub` | 官方客户端依赖，不为 UI 改协议 |
| UI API | `/ui/api/*` | 浏览器专用，可有不同分页/排序/批量语义 |
| V1 | `/ui_v1/` | 默认产品界面 |
| V2 | `/ui_v2/` | 开发测试版 |
| 共享层 | `/ui_shared/` | 只放真正无版本耦合的静态资产 |
| 兼容入口 | `/ui/` | 跳转到 V1 |

`UI_ENABLED=false` 时所有 UI 静态挂载和 `/ui/api/*` 都 404；协议面不受影响。

服务端 UI 代码集中在 `src/ui/`；前端是 `public/` 下的原生 ES modules，无构建步骤。

## 2. UI 不变式索引

> 编号 1–39 保持稳定，供代码/测试注释引用。这里不保存“为什么当时改过”，只保留当前规则。

1. **action 返回结果，组件呈现结果。** 请求发出不等于成功；成功态只能由 action 的真实结果驱动。
2. **原地反馈优先。** pending/success 尽量落在用户刚操作的控件；toast 只解释跨控件或需要补充说明的结果。
3. **同一视图刷新按行对账。** 未变化的行不重建，避免缩略图重载、焦点丢失和无意义 DOM 写入。
4. **dialog 的 Promise 在决定发生时结算。** `close/cancel` 只作旁路兜底，不能让主流程依赖浏览器事件是否派发。
5. **删除成功后行立即消失并移交焦点。** 后台刷新负责补齐，不让键盘焦点掉回 `<body>`。
6. **异步视图都有竞态 ticket/abort 守卫。** 迟到响应不能覆盖新状态，被取代的请求不算失败。
7. **推送是轮询加速器，不是替代品。** WS 在线时轮询退为 60s 看门狗；失联回 10s，连续失败进入冷却。
8. **后台标签页主动断开推送。** 隐藏态交给低频轮询，避免无意义重连和 DO 常驻。
9. **收藏/置顶就地更新并采纳服务端元数据。** 行签名必须包含会影响展示/排序的字段。
10. **深链接用 `#Type-hash` 打开预览。** 编解码后拒路径分隔符；迟到请求不能重新打开已关闭的 dialog。
11. **列表更新不做 view transition 或入场错峰动画。** 首屏和刷新都优先稳定、快速。
12. **筛选控件先更新，列表等响应。** 用户操作后立即给视觉反馈，旧结果只作 busy 占位。
13. **类型切换不视为全新页面。** 仍按 key 对账，不整表重建。
14. **统计归属与当前视图不一致时隐藏，不显示旧数字或 0 假值。**
15. **批量动作后的焦点恢复只接管“无主焦点”。** 用户已经把焦点放到别处时不得抢回。
16. **选择集中的行对象必须与列表同步。** 行更新后选择条不能继续握旧快照。
17. **行内动作槽位固定。** 粗指针命中区 ≥44px，危险动作留间距；禁用控件仍要可获得原因提示。
18. **“清除筛选”与标准按钮同形，只变语义色。** 仅在确实有筛选时出现。
19. **表单错误挂到字段。** 只有字段自身不合法才设 `aria-invalid`；网络/500 不能冒充字段错误。
20. **页脚项目名是仓库入口。** 相关/致谢链接可展开，但不能让它们成为完成任务的必经路径。
21. **窄屏分页主动作保持同一行且靠右。** 不让页码标签被整行样式误伤。
22. **顶栏状态名不换行。** 极窄屏先收间距，最后才隐藏纯装饰。
23. **窄屏工具栏保留页大小、刷新和筛选文字。** 空间不足时换行，不靠隐藏功能解决。
24. **会改变结果集成员资格的筛选变化必须清选择集。** 排序/翻页/页大小不属于成员资格变化。
25. **选中态点击行体切换选择；点空白清空选择。** Shift 范围选择与文字划选不能互相破坏。
26. **hover 预览只是渐进增强。** 仅细指针启用；只在内容真实裁切时出现；`pointer-events:none`；最多 6 行；完整内容仍靠预览按钮。
27. **回收站固定三个出口：恢复、预览、彻底删除。** 彻底删除必须确认，只允许删除 `IsDeleted != 0` 的记录。
28. **长批量可以中止，但写操作只在批次边界停。** 已生效数量必须如实保留；读批量可取消在途请求。
29. **文本编辑保存为新记录。** Text hash 随正文变；保存成功后 dialog 改指向新记录，失败时保留输入；正文 >1 MiB 不开放编辑。
30. **状态徽标靠内容列右缘；内容格过窄时给正文让行。**
31. **“删除”只用于不可撤销操作。** 软删统一叫“移动到回收站”。
32. **预览页脚左侧固定放视图级危险动作。** 活跃=移动到回收站，回收站=彻底删除。
33. **回收站的“清空回收站”不要求先选择记录。**
34. **向下滚隐藏顶栏，向上滚恢复。** 用位移保持布局稳定。
35. **模态打开时 toast 宿主进入最上层 dialog。** 只保留一套 toast，不另造“框内假 toast”。
36. **快捷键只是加速器。** 每个键位都有可见等价入口；帮助表与派发器同源。
37. **键盘可用性不仅是快捷键。** Tab/方向键必须能完成搜索、列表动作、分页、dialog 和批量操作。
38. **键盘走查必须用真实按键执行。** 代码“看起来可达”不算验证。
39. **行内 action 读取当前 `ref.item`，不能使用构建时快照。**

## 3. 共享层

`public/ui_shared/` 只允许：品牌资产、无版本耦合的纯数据模块、未来真正两版共享的翻译资源。

不要把 `api`、`dom`、`format`、`filters`、`messages` 等“实现有意不同”的模块抽进共享层；共享不是目标，减少重复维护成本才是目标。

## 4. 鉴权与会话

- UI 登录成功后使用 `base64url(payload).base64url(HMAC-SHA256)` 签名 Cookie，payload 为 `{u, exp}`；
- 密钥由 `PASSWORD` 派生，改密码会整体失效旧会话；
- 不建服务端会话表；登出只清本机 Cookie；全设备撤销的候选方案只在 Issue #3 跟踪；
- `/ui/api/*` 接受会话 Cookie 或 Basic；官方协议面只接受 Basic；
- UI 状态变更同时校验 `Origin` / `Sec-Fetch-Site`。

## 5. UI API

完整路由表以 `src/ui/routes.ts`（装配）与 `src/ui/routes/*.ts`（各路由组）及 `test/ui-guard.test.ts` 的 `EXPECTED_API_ROUTES` 为准，不在文档复制数量。

| 能力 | 当前约束 |
|---|---|
| 历史列表 | `pageSize <= 500`，6 个排序字段，正文截断 500 码点并标记 `textTruncated` |
| 数据读取 | UI 数据端点支持单区间 Range；协议侧不跟随这一偏离 |
| 文本新建 | `POST /ui/api/history`，正文 ≤1 MiB |
| 单条更新 | 收藏/置顶/软删/恢复/访问时间 |
| 批量更新 | ≤100 条/批，有界并发，广播在 DO 内逐条保序 |
| 批量元数据 | ≤100 条，可取完整正文 |
| 批量彻底删除 | 只处理回收站记录，并清 R2 数据 |
| 保留策略 | 数字=覆盖；`null`=清除覆盖回落 env；缺省=不改 |

JSON 默认 `Cache-Control: no-store`；数据端点可用 `private, max-age=60` 复用预览字节。

UI 成功复制/下载会推进 `LastAccessed`，但请求回显 `version` 与 `lastModified`，避免一次“读取”制造同步版本变化。

## 6. 回收站语义

软删只置 `IsDeleted=1`，**保留数据文件**。因此图片/文件可恢复。

真正释放 R2 空间的出口只有：

- 单条/批量“彻底删除”；
- “清空回收站”；
- 超过 30 天的硬删清理。

“数据不可用”只表示对象确实缺失，不代表记录处于回收站。

## 7. 安全

- 前端不用 `innerHTML` 注入用户内容；
- 附件采用默认-deny 内联白名单：图片（除 SVG）、纯文本/CSV/Markdown、JSON、PDF 可内联，其余下载；HTML/XML 家族额外 CSP sandbox；
- `?next=` 只接受同源目标；
- UI JSON 写端点要求 `application/json`；
- CSP 集中在 `public/_headers`；
- 浏览器会为同源请求自动携带凭据，因此附件渲染与第三方 viewer 必须按同源 XSS 威胁模型处理。

尚未实施的文档预览与图片缩略图分别只在 Issue #4 / #5 跟踪；未实现功能不写进当前 UI 规格。

## 8. 设计与可访问性

- 系统字体，不依赖 Web font；
- 语义色令牌，浅/深主题同构；
- 粗指针命中区 ≥44px；
- 信息不能只靠颜色或 hover；
- dialog 页眉/页脚固定，正文是唯一可收缩区；
- 键盘入口、focus 恢复、`aria-invalid` / `aria-describedby` 属功能正确性，不是额外打磨。

V2 可以破坏性重构视觉/信息架构，但不能绕过同一套 UI API、安全模型和核心交互不变式。

## 9. 验证

| 层 | 工具 |
|---|---|
| 自动测试 | `test/ui*.test.ts`、相关协议/安全测试 |
| 真实浏览器 | `test/manual/probe-ui-v1.mjs`（V1）/ `test/manual/probe.mjs`（V2） |
| 交互状态 | `test/manual/states.mjs` |
| 截图人工检查 | `test/manual/shoot.mjs` |

四个脚本共用 `test/manual/cdp.mjs` 的 CDP 原语（起浏览器 / 发命令 / 登录注入 Cookie / 收错误）；
该模块不含判据，只去重复。判据的“跳过”与“通过”必须区分，且必须影响退出码。

三条纪律：

1. DOM 存在不等于用户看得见；几何/焦点/溢出必须读真实浏览器；
2. probe 的“跳过”与“通过”必须区分；
3. 判据必须影响退出码，只写 `console.log` 不算验证。

改前端至少覆盖一档宽屏和一档窄屏，并确认零 console error、零失败请求。

## 10. 性能预算

- overview 与列表并发，activity 不阻塞首屏；
- 首屏 CLS 目标≈0；
- 一页最多 500 行，列表正文服务端截断；
- 推送在线时轮询 60s 看门狗，失联 10s，隐藏页 30s；
- 行 DOM 仅在签名变化时重建；
- 无变化的 chrome 层状态不写 DOM；
- 不做 view transition，也不做首屏逐行入场动画。

探针读数只能在同一轮环境里作前后对比；跨机器/跨会话只看趋势。
