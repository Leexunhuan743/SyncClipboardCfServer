## 0. 方法与口径

四个视角并行，每个结论都要求**可复核的证据**，不接受"看起来没问题"：

| 视角 | 做法 | 产出 |
|---|---|---|
| 终端用户 | 真实登录、CDP 驱动真实页面，逐条复现交互缺陷（含"结果与预期不符"的实测输出） | A-01…A-14 |
| 视觉与交互 | 断点 320/390/768/1024/1440 + 200% 缩放 + 200% 字号实测；对比度用 sRGB→相对亮度自行计算 | A-13、A-19、A-28 |
| 工程实现 | 逐个模块读完（33 个 JS 模块 / 5 张样式表）；重复行扫描、未使用导出扫描、未使用令牌扫描、纯函数去重 | A-15…A-18、A-31 |
| 质量保障 | 首屏请求/字节/CLS/LCP 实测；注入点全量扫描；错误码 × 状态矩阵；竞态与连点复现 | A-02、A-08、A-20…A-27 |

**证据规则**：每条结论要么是 `文件:行`（我读过的那一行），要么是一次可复现的实测
（脚本、命令、量出的数字）。无法验证的一律标注"未验证"。
**对照基线**：改动前的数字都来自本轮实测，不是估计。

## 1. 结论摘要

**做得好、不该动的部分**（审计确认，非假设）：

- **注入面基本为零**：`public/ui/**` 里 `innerHTML` / `outerHTML` / `insertAdjacentHTML` /
  `srcdoc` / `document.write` / `eval` / `new Function` **各 0 处**（`dom.js` 根本不提供插 HTML 的路径）。
  剪贴板内容完全不可信（任何同步设备都能推任意文本/文件名），而它们只流向
  `textContent` / `title` / `aria-label`；按钮图标来自常量表，从不拼接数据。
- **CSP 严格且确实下发**：`default-src 'none'` + `script-src 'self'`，**没有 `unsafe-inline`/`unsafe-eval`**，
  且补了常被漏掉的 `object-src` / `base-uri` / `frame-ancestors`。实测在 `/ui/app/`、
  `/ui/js/*`、`/ui/` 上都带全套安全头（`run_worker_first` 经过 Worker 也保留了 `_headers`）。
- **状态与 URL 经过白名单校验**：`filtersFromUrl` 校验 `types/sort/range`、夹取 `page/pageSize`、
  截断 `search`；服务端再校验一次（`sort=constructor` 这类原型链陷阱用 `Object.hasOwn` 关掉了）。
- **竞态守卫是真的**：`createLatestGate` 会 abort 上一个请求并丢弃过期响应；轮询/推送/概览各持一个。
- **无障碍基础扎实**：161 个图标按钮**全部**有 `aria-label`+`title`；`:focus-visible` 在每类控件上实测存在；
  原生 `<dialog>` 的焦点陷阱与 Esc 关闭有效；`prefers-reduced-motion` 下动效被清零且有兜底定时器；
  所有 hover 样式都包在 `@media (hover: hover) and (pointer: fine)` 里。
- **响应式没有横向溢出**：320/390/768/1024/1440 与 200% 缩放下 `pageOverflowX` 全为 0。

**风险画像**：安全问题**不是**这个前端的短板（注入面为零、CSP 到位）；
真正的短板集中在**"状态同步与交互稳定性"**（前进后退、焦点、重复提交、可见性反馈）
和**"无障碍的键盘可达性"**（批量条、列表导航、若干未命名控件），
以及一处**首屏 CLS 0.90** 的性能缺陷。

### P1 —— 高频、可复现、影响明确

| A-02 | **首屏 CLS 0.90**：骨架屏在真实首屏里**从未渲染**（`render()` 只在数据落地后才跑），且骨架行数写死 6 行对默认 50 行 | 实测：加载中 `ghost=0`、文档高 804px（页脚在 736px 处，**在视口内**）；数据落地后 4454px，页脚/分页被整段顶出屏幕；单次位移 0.8987 | 每次打开页面，内容到达的瞬间整页往下跳一次 —— 光标还停在原处时按钮已经换位 | **已修** |

## 6. 第四轮：**线上截图走查**抓到的两个真缺陷（用户要求"截图看看"）

前几轮的验证都走"脚本断言 + 本地截图"，两个缺陷因此都漏了。这一轮把部署后的线上界面真的截图看了一遍，
**一眼就看出两个问题**——它们的共同根因是 `createDialog.open()` 的清理时机：

| ID | 缺陷 | 现象（线上与本地一致） | 根因 |
|---|---|---|---|
| A-39 | **删除确认框没有正文**：只剩标题「删除这条记录？」与两个按钮 | 实测 `dialog__body` 的 `textContent` 是**空串**。"将删除「…」。所有同步设备上的这条记录也会被删除；服务端会立即清除数据文件（不可恢复）"整段看不到 —— 而这是用户判断要不要删的**唯一依据** | `createConfirm.ask()` 先把说明 `<p>` append 进 body，随后 `dialog.open()` 执行 `clear(body)` 再按 `spec.body(ctx)`（一个空 div）重建 ⇒ 刚塞进去的说明被冲掉 |
| A-40 | **预览框没有动作按钮**：只剩「关闭」 | 文本记录的「复制内容」、图片记录的「下载/复制图片」全部不渲染。而"复制失败时自动打开预览"的提示语正是让用户去预览里复制 —— 那条退路是断的 | `createSheet.open()` 先把动作按钮 `prepend` 进 foot，随后 `dialog.open()` 执行 `clear(foot)` 再按 `spec.foot(ctx)`（只有「关闭」）重建 ⇒ 动作按钮被冲掉 |

**修法**（不是"再补一次 append"，那样下次还会被冲掉）：把**内容与按钮都改成参数交付**，
让 `open()` 成为正文/页脚的唯一拥有者 —— `content` 覆盖正文，`buttons` 追加在基础按钮**之前**
（「关闭」永远在最后）。调用方只给数据，不再预操作一个"马上会被 clear 的节点"。

**为什么前几轮没抓到**（这是这一轮最值得记的一条）：`states.mjs` 的预览断言**收集了** `actions`
字段却从来没人断言它；确认框断言只检查"打开了/能取消"，没检查正文。
**脚本收进 result 的字段必须有人断言，否则它只是一段没人读的日志。** 三条断言已补：
预览必须有动作按钮（文本与图片两种记录各一条）、确认框必须说清"删的是哪一条 + 后果"。

## 7. 开发环境的一个坑（本轮踩到，记在这里）

**新加的静态模块不会立刻被 `wrangler dev` 提供**：`public/` 的资源清单在启动时构建，
运行中新增文件会返回 **404**（已存在的文件改动则会热更新）。
症状很吓人：页面完全没有行、`booted` 为 null、控制台**零错误**（模块 404 在模块图上表现为整图加载失败）。
**规则：新增（而不是修改）`public/ui/**` 下的文件之后，重启 dev server 再判断页面。**
