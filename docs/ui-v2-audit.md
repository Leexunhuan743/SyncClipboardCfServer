## 1. 结论摘要

**做得好、不该动的部分**（审计确认，非假设）：

- **注入面基本为零**：`innerHTML` / `outerHTML` / `insertAdjacentHTML` / `srcdoc` / `document.write` /
  `eval` / `new Function` **各 0 处**（`dom.js` 根本不提供插 HTML 的路径）。剪贴板内容完全不可信
  （任何同步设备都能推任意文本 / 文件名），而它们只流向 `textContent` / `title` / `aria-label`。
- **CSP 严格且确实下发**：`default-src 'none'` + `script-src 'self'`，没有 `unsafe-inline` / `unsafe-eval`，
  且补了常被漏掉的 `object-src` / `base-uri` / `frame-ancestors`。
  > ⚠️ 那次实测打在 **`/ui/`**（当时 V2 的入口，有页面、走 `_headers`；2026-09-19 改名后 `/ui_v2/`
  > 本身没有页面）。**今天 `GET /ui_v2/` 回的是 Worker 出的 `notFoundPage`，那套头与 `_headers`
  > 不是同一份**（它带 `style-src 'self' 'unsafe-inline'`、没有 `script-src 'self'`）——
  > 别把这条读成"`/ui_v2/` 的响应头也如此"。
- **状态与 URL 经过白名单校验**：`types` / `sort` / `range` 白名单，`page` / `pageSize` 夹取，`search` 截断；
  服务端再校验一次（`sort=constructor` 这类原型链陷阱用 `Object.hasOwn` 关掉）。
- **竞态守卫是真的**：`createLatestGate` 会 abort 上一个请求并丢弃过期响应。
- **无障碍基础扎实**：**161 个图标按钮全部**有 `aria-label` + `title`；`:focus-visible` 每类控件实测存在；
  原生 `<dialog>` 的焦点陷阱与 Esc 关闭有效；`prefers-reduced-motion` 下动效清零且有兜底定时器；
  所有 hover 样式都包在 `@media (hover: hover) and (pointer: fine)` 里。
- **响应式没有横向溢出**：320/390/768/1024/1440 与 200% 缩放下 `pageOverflowX` 全为 0。

**风险画像**：安全**不是**短板（注入面为零、CSP 到位）；短板集中在**"状态同步与交互稳定性"**
（前进后退、焦点、重复提交、可见性反馈）与**"键盘可达性"**，外加一处**首屏 CLS 0.90**。

### 2.1 状态同步与交互稳定性

| ID | 问题 | 现在的做法 |

| A-06 | **菜单 Esc 顺带清空选择集**（两个监听器在**同一节点**上，`stopPropagation()` 压不住同节点的另一个） | keydown 移到**捕获**阶段；Esc 后焦点还给锚点 |
| A-25 | **`?page=999999` 死胡同**（服务端返回 `total` + 空列表 ⇒ 渲染成"还没有任何记录"，空状态的按钮还不重置 `page`） | 越界页码夹回最后一页重发一次 |

## 3. 待定（需要决策，未动）

| ID | 问题 | 为什么要一句确认 |
|---|---|---|
| **A-28** | **`backdrop-filter` 主导滚动成本**：`.appbar` 粘顶 `blur(12px)` + `.filters` `blur(8px)` + 5 个 sticky 表头单元格。实测滚动最差帧：有它 **25.3ms**（超过 16.7ms 预算），去掉后 **7.3ms**；全页布局成本 ≈0ms | 视觉取舍：毛玻璃是当前观感的一部分。**替代方案**：把 `.filters` 的毛玻璃换成不透明底色、只保留顶栏（代价几乎全部来自浮动层，而顶栏只有 56px） |
| **A-29** | **`pageSize=500` 无护栏**：190KB JSON + ~17.5k 个节点（50 行 ≈14.9ms 构建，500 行 ≈150ms 阻塞） | 产品决策：保留 500 档、还是删掉 / 加二次确认 |
| **A-30** | 5 张渲染阻塞样式表，其中 `overlay-v2.css`（24.9KB / 占 CSS 32%）**首屏根本用不到**（只有对话框 / 抽屉 / 菜单 / 提示条） | 需要用户拍板：合并为 `app.css` + 把 overlay 移出关键路径，代价是改守卫与设计文档的文件分层，收益有限 |
| **A-35** | 退出登录在离线时只跳转、不清 Cookie（Cookie TTL 24h）⇒ 共享浏览器上下一个访问者可能直接进界面 | 属服务端 / 会话语义，另一层 |
| **A-36** | `/ui/api/*` 响应缺 `X-Content-Type-Options: nosniff`（静态资源有） | 影响很低（JSON + 严格 CSP），但基线头不一致。**实测今天仍缺** |
| **A-37** | 每次加载多打一次 `/ui/api/activity`（overview 不含活动趋势） | 服务端把 `days` 合进 overview；一次多余往返，用户几乎无感 |

**明确不做**（连同理由）：

- **A-34 的 `tabindex="0"`**：会自灭的元素一旦进了 Tab 顺序，焦点可能在它消失的瞬间掉到 `<body>` ——
  那比"读不完"更糟。
- **A-31 的 roving tabindex**：目标只是"列表能被键盘浏览"，而它的手段是**减少** 150 个 Tab 停靠点 ——
  那是可感知的行为改变。方向键是纯增量。

## 4. 三轮走查的结论（过程细节见 `git show <hash>:docs/ui-v2-audit.md`）

**第二轮 · 补做三项决定**：A-31（见上）、A-38（只外提纯逻辑）、A-32/A-34（不引入"承诺了却做不到"的语义）。

**第三轮 · 登录页纳入冒烟**（此前只有一张截图、零断言）：补 14 条断言（唯一 `<h1>`、`<label for>` 绑定、
`required`、`autocomplete`、`role="alert"` 的错误区、空提交本地拦截 + 焦点回字段 + `aria-invalid`、
已登录直接跳列表页、`?next=` 的同源白名单四种回落）。**一个刻意的测试设计**：这一节**不打失败密码** ——
服务端对登录失败有限速，冒烟脚本要反复跑，用错密码跑几次会把本机 IP 关进小黑屋、连脚本自己的登录都失败。
**测试稳定性优先于多覆盖一条文案。**
顺带复查抓到两处**自己引入**的问题：HTML 注释里混进 ESC 控制字符（PowerShell 的 `` `e `` 转义）、
"保留理由写在令牌文件里"实际没写。**教训：审计的结论也要被审计一次。**

**第四轮 · 线上截图走查**（用户要求"截图看看"）→ 抓到 A-39 / A-40，见 §2.5。同时确认线上：
登录流程、列表渲染、抽屉（**保存按钮文字在线上生效**）、行菜单、回收站视图、空状态、390px 移动端、
深色主题、资源完整性（37/37 资源 200；JS/CSS 的缓存头与 A-27 的修复一致；HTML `max-age=0`）、
零失败请求、零控制台错误。
**一个诊断上的坑**：无头浏览器**不会自动读系统代理**，直连 `*.workers.dev` 会超时 ——
表现为"页面全白、`booted` 为 null、控制台零错误"，与"模块 404"的症状几乎一样。
**这台机器上对线上做截图 / 探针，必须先给浏览器指定代理，否则得到的是假象。**

**开发环境的坑**：新加的静态模块不会立刻被 `wrangler dev` 提供（`public/` 的资源清单在启动时构建，
运行中**新增**文件返回 404，已存在的文件改动则热更新）。症状同上（页面无行、零错误）。
**规则：新增 `public/ui_v2/**` 的文件之后，重启 dev server 再判断页面。**

## 5. 未验证项（明确声明）

1. 没有跑真实读屏（NVDA / VoiceOver），所有"读屏会怎样"都是由 DOM / ARIA 契约推断的。
2. `(pointer: coarse)` 在无头浏览器里不会命中 ⇒ A-14 / A-33 是由 CSS 规则 + 实测几何**推算**，
   没有在真机上用手指验证。
3. 对比度是按 sRGB 公式自算的，没采样渲染后的像素（`color-mix()` / 半透明叠加的最终色值可能略有偏差）。
